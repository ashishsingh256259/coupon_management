Hash Table — Memory Map Visualization
Each coupon code is converted to an array index via: h(code) = (Σ ASCII values) % table_size
Table size: 101 buckets  |  Collision handling: Chaining (linked list per bucket)  |  Avg lookup: O(1)
Hash Table O(1) avg
The most critical data structure in this system. Each coupon code (key) hashes to a numeric index, directly mapping to the coupon record in memory — no linear scan needed.

Hash function: h(code) = (Σ ASCII) % table_size
Collision resolution: Chaining (each bucket has a linked list). 
// JavaScript object = Hash Table
const hashTable = {
  "SAVE20": { discount: 20, limit: 5 },
  "NEW50":  { discount: 50, limit: 2 }
};
// Lookup: O(1) — instant
let rec = hashTable["SAVE20"];
💡 Used for: coupon lookup at checkout — must handle millions of requests instantly
Stack (LIFO) O(1) ops
Last In, First Out — the most recently applied coupon is always undone first. No database rollback needed. The Stack tracks the entire coupon application history for one checkout session.

push() = apply coupon → top of stack
pop() = undo → removes top element 
// Array as Stack
let stack = [];
// Apply coupon → push
stack.push("SAVE20");
// Undo → pop (LIFO)
let removed = stack.pop();
// Both operations: O(1)
💡 Used for: session-level undo of coupon applications — instant O(1) rollback
Queue (FIFO) O(1) ops
First In, First Out — the fairest distribution mechanism for limited flash-sale coupons. Users join at the rear and are served from the front. No one can skip the line.

enqueue() = user joins rear → push()
dequeue() = serve front user → shift() 
// Array as Queue
let queue = [];
// User joins → enqueue
queue.push("User101");
// Serve next user → dequeue
let next = queue.shift();
// enqueue: O(1), dequeue: O(n)
💡 Used for: flash sale coupon distribution — fair FIFO access for 500 limited coupons
Linked List (Dynamic) O(1) insert
Each transaction record is a node that points to the next. New records are inserted at the head in O(1). Unlike arrays, no pre-allocation — memory grows exactly as needed.

Each node stores: user_id, coupon, timestamp, discount, order_id 
// Node structure
class TxnNode {
  constructor(data) {
    this.data = data;
    this.next = null; // pointer
  }
}
// Insert at head: O(1)
let newNode = new TxnNode(txn);
newNode.next = head;
head = newNode;
💡 Used for: transaction log — continuous growth, no wasted memory, O(1) insertion
